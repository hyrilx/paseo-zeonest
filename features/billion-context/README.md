# Billion Context

为同一 Paseo 宿主管理一个独立的 Bili 服务，让 Pi 与 dashboard 使用同一个固定地址。在侧边栏打开总览，在当前会话的 Command Center 打开精确会话详情，不占用聊天框胶囊区。子功能默认关闭，启停通过整体重载 Zeonest 生效。

## 准备与启用

托管启动器支持 macOS、Linux 宿主，需要 Node.js 22 及以上，并已安装提供 `bili start` 的 billion-context CLI。Pi 还需安装并加载 billion-context 扩展；环境变量不会替你安装扩展。Windows 原生宿主尚不支持此启动器，可使用 WSL/Linux 宿主。

1. 在 Billion Context 配置页填写「Bili 可执行文件」。默认 `bili`，从 **Paseo daemon 的 PATH** 查找；找不到时填写可执行文件的绝对路径。这里只接受命令名或文件路径，参数由功能提供，不经过 shell。
2. 按需配置「客户端访问地址」，本机桌面连接可留空。远程连接见下文。
3. 启用功能并重载 Zeonest。功能会启动独立服务；已有托管进程通过身份校验后直接复用，不重复启动。
4. 查看配置页的服务状态，确认固定地址、PID、版本与实例身份。首次启动时分配随机可用端口并持久化，后续启动与崩溃恢复沿用该端口。
5. 在下一次打开 Pi provider 会话时注入固定地址。已运行的 Pi 不会被自动中断或改写环境；需要在空闲时重新打开。

无需手动执行 `bili start`，也不再从日志或历史端口中挑选实例。旧版保存的 `serverOrigin` 仅为兼容设置结构而保留，不参与托管端点选择；配置页不再显示该输入项。其他手动启动或 inline 实例不会被接管、合并或停止。

## 配置页服务控制

配置页每 3 秒刷新服务状态，并提供手动刷新。显示运行状态、固定地址、PID、Bili 版本、实例 ID、UTC 启动时间和最近的服务错误。

| 操作 | 行为 |
| --- | --- |
| 启动服务 | 在已保存的固定端口启动；已经运行时复用。首次启动才分配端口。 |
| 停止服务 | 二次确认后，仅停止身份已验证的托管进程。停止意愿会持久化，不会被监控器或插件重载自动拉起。 |
| 重启服务 | 二次确认后，在原端口停止并重启托管进程。期间依赖它的 Pi 请求可能失败。 |
| 强制更换端口 | 二次确认后停止已验证的托管进程，分配不同的可用端口并启动新实例。旧 Pi 仍持有旧地址，需在空闲时重新打开。 |

强制换端口不会自动中断、重开 Pi，也不会创建或调整隧道。确认操作携带当前服务记录版本；记录已经改变时必须刷新并重新确认。换端口的「强制」指显式改变固定端口，不指强杀进程：停止最多等待 6 秒，不发送 SIGKILL。

功能关闭或可编辑配置无效时，仍可查看状态或显式停止已托管服务；启动、重启和换端口需要有效配置，并先启用功能、重载插件。重载、关闭插件和退出 Paseo 均不主动停止独立服务。需要结束服务时使用配置页的停止操作。

端口被其他进程占用时不静默换端口，也不按端口或 PID 猜测后杀进程。确认换端口可以避开占用，但只有原记录的进程已退出、身份检查允许安全释放记录时才执行；仍存活但无法验证的进程必须先排查。

## Pi 环境与失败处理

原生 `agent.open.before` hook 仅处理 `provider: "pi"`、`purpose: "interactive"` 的会话打开请求。创建、恢复和刷新经过同一逻辑；历史读取与其他 provider 不注入。保留完整请求及原环境，合并：

```text
BILI_PI_INLINE=0
BILLION_CONTEXT_ATTACH=http://127.0.0.1:<固定端口>
```

服务先通过 manifest 与 health 验证，再返回环境。启动失败、固定端口冲突、服务被手动停止或身份无法验证时，hook 抛错并阻止这次 Pi 打开，不退回 inline 或其他 Bili。显式禁用原生接入的 `BILLION_CONTEXT_PLUGIN=0`、`BILI_NATIVE_PI=0` 或 `BILI_PROVIDER_REWRITES` 与此模式冲突，会明确报错。

服务启用时每 5 秒检查一次，需要恢复时在原端口重启。首次分配端口遭遇绑定竞争可重试，已持久化端口不会自动漂移。启动就绪等待上限为 10 秒；monitor 与用户打开会话共享启动任务，避免同时创建多个进程。服务不可用时，先在配置页查看并处理错误，再重试打开 Pi。

启动参数由功能固定提供：

```text
bili start --host 127.0.0.1 --port <固定端口> --no-auto-update
```

子进程设置 `BILI_STRICT_PORT=1`、`ACP_AUTO_UPDATE=0`、`ACP_AUTO_RESTART_ON_UPDATE=0`，并移除继承的 Bili launcher 父进程标记，避免依附当前 Pi 生命周期或自动升级后换进程。Bili 的配置初始化、数据持久化和 dashboard 内容仍由 Bili 自己负责。

## Dashboard 与会话入口

- **侧边栏「Billion Context」**：自动打开托管实例的全局总览，无需再次选择实例或工作区。
- **当前会话的 Command Center**：搜索「Billion Context」或「上下文详情」，选择「Billion Context：查看当前会话详情」。使用原生 `agent` 上下文中的当前工作区与会话，不轮询 agent 列表。

两个入口先验证或启动同一托管端点，再查询所需路由。详情读取 provider 的 `persistence.sessionId`，只读请求 `GET /__bili/plugin/status?conversationId=<provider-session-id>`，使用返回的真实 Bili `sessionId`。不使用 `fallback=latest`，不按标题、目录或最近活动猜测。未建立压缩会话、归档、身份切换或响应无效时显示错误，不打开其他会话。手动停止服务后，入口会提示先启动服务。

桌面端仍使用 Paseo 原生 `navigation.openBrowser`。SDK 0.15.4 要求浏览器标签归属一个现有工作区，侧边栏又不提供当前工作区，因此总览自动用首个可用工作区放置标签；数据范围仍是整个托管实例。详情入口始终用当前会话所属工作区。没有可用工作区时显示错误。

Web、iOS、Android 自动调用原生外部打开接口；拦截或失败时保留明确链接。桌面跳转失败不会自动切到外部浏览器。原有多实例响应的客户端兼容处理保留，当前托管服务端不会做多实例发现或选择。

**独立插件页内嵌原网页仍暂缓。** SDK 0.15.4 的文档预览组件禁止脚本，不能运行原 dashboard；本次托管改造不改变浏览器承载方式，需要宿主提供相应网页 API。

### 客户端访问地址

留空时浏览器使用宿主的固定回环地址。也可填写 HTTP(S) 源地址，或在端口位置使用英文半角 `{port}`：

```text
http://my-host:{port}
```

托管端口为 `43210` 时，总览地址展开为 `http://my-host:43210/__bili/`，详情路径为 `/__bili/#/session/<encoded-session-id>`。模板不写回设置；不接受路径、查询参数、账号或凭据。

浏览器运行在客户端，`127.0.0.1` 指客户端本机。远程宿主或移动端需提前建立受保护的隧道/反向代理，并填写客户端可达的地址。固定的转发端口直接填数字，不用 `{port}`。模板只替换端口，不负责连通性，也不会暴露宿主监听。Dashboard 可能含完整对话内容，不应直接公开到未受保护的网络。

## 状态、身份与资源

托管记录位于 `$PASEO_HOME/zeonest/billion-context/service.json`；未设置 `PASEO_HOME` 时为 `~/.paseo/zeonest/billion-context/service.json`。同一 Paseo home 共享一个服务记录。记录包含端口、运行意愿、进程身份、记录版本及安全错误信息，不含对话正文或凭据。

状态目录和记录拒绝符号链接，读取有大小上限；记录采用临时文件、同步写入、原子替换与 `0600` 权限，跨控制器操作使用进程锁。损坏或无法验证的记录不覆盖。不要在服务运行时手动编辑或删除记录，否则会丢失可靠的进程归属信息。

只有 health 返回的 PID、实例 ID 和启动时间均与记录一致，才复用或发送停止信号；正在完成的首次启动还会核对本功能记录的子进程及启动时间窗口。外部同端口实例、PID 复用、无法验证的存活进程均报错。不会因为另一个实例能读取同一持久化会话而视为自己所有。

设置与服务控制 RPC 在 `server/settings.ts` 同步声明，关闭时仍可使用；业务 RPC 在 `server/rpc.ts` 同步声明并在内部拒绝未启用或已停止的调用。`server/index.ts` 管理启用状态、原生 hook 和监控器。cleanup 移除 UI、命令、hook、轮询及监控，阻止迟到回调；保留独立服务与记录，不修改 daemon 的 `pluginsEnabled`，不自动 reload 会话。
