# Billion Context

在侧边栏提供 billion-context dashboard 总览入口，在聊天框底部提供「上下文详情」胶囊。新增功能默认关闭，启停通过整体重载 Zeonest 生效。

## 使用

1. 先运行 billion-context。Billion Context 配置页的「宿主侧实例地址」默认留空，自动发现代理和 Pi inline 实例，无需填写随机端口。
2. 启用功能并整体重载插件。配置保存后，下次打开入口即使用新地址；功能关闭时仍可编辑配置。
3. 点击侧边栏「Billion Context」，自动打开所选实例的全局总览，无需再次选择工作区或点击打开。
4. 点击聊天框底部「上下文详情」，自动打开当前会话的详情。服务端读取当前 agent 的 `persistence.sessionId`，查询精确映射；使用胶囊携带的工作区，不让用户重新选择。

桌面端通过 Paseo 原生 `navigation.openBrowser` 打开工作区浏览器。SDK 0.15.4 要求浏览器标签归属一个现有工作区，但侧边栏不提供当前工作区信息，因此总览入口自动选用宿主返回的第一个可用工作区放置标签；总览的数据范围仍是整个 billion-context 实例。详情入口始终使用当前会话所属工作区，不会改选。没有可用工作区时显示错误。

Web、iOS、Android 自动调用原生外部打开接口。浏览器拦截或打开失败时保留明确链接，用户可点击重试。桌面跳转失败不会自动切到外部浏览器。

发现多个可用实例时停留在实例选择页，选择后重新验证并打开。其他错误显示重试入口；总览打开失败后可改选放置浏览器标签的工作区。正常流程不显示工作区选择器。

Paseo SDK 固定为 0.15.4，没有原有上下文圆环的点击扩展点，因此使用独立胶囊。SDK 的文档预览组件禁止脚本，不能承载 dashboard。

## 地址配置

- **宿主侧实例地址**：留空启用自动发现；填写 HTTP(S) 源地址则固定使用该实例，不再读取发现记录。不接受路径、查询参数、账号、密钥或模板。
- **客户端访问地址**：可选，留空时沿用发现或填写的宿主侧地址。可填写固定源地址，也支持端口位置的 `{port}` 模板。远程连接时可填写经过安全隧道转发的客户端地址，须指向同一个实例。

例如，客户端地址填写 `http://my-host:{port}`，选定的实例地址为 `http://127.0.0.1:43210`，总览链接会展开成 `http://my-host:43210/__bili/`。会话详情使用相同展开规则。模板在选择并验证实例后展开，不写回配置；手动指定的实例也适用。实例地址未显式指定端口时，HTTP 使用 80，HTTPS 使用 443。仅支持英文半角 `{port}`，且只能放在源地址的端口位置。

如果隧道使用固定的本地转发端口，直接填写该数字，例如 `http://127.0.0.1:8888`，不要使用 `{port}`。模板只替换数字，不会创建或调整隧道。

总览路径为 `/__bili/`；会话路径为 `/__bili/#/session/<encoded-session-id>`。不要将完整 Web UI 路径填入源地址。

### 自动发现来源

在 Paseo daemon 所在宿主、以 daemon 的运行用户读取 billion-context 状态目录：`$XDG_STATE_HOME/billion-context`；未设置 `XDG_STATE_HOME` 时为 `~/.local/state/billion-context`。

- 代理：读取 `proxy-origin`、`instances/*.json` 和旧版 `instances.json`。JSON 记录需有仍存活的 PID，且未标记释放端口；兼容旧版纯地址 `proxy-origin`。
- Pi inline：从默认 `bili.log` 最后 512 KiB 提取 `[inline] web UI listening on ... (loopback only)` 启动记录，适配随机端口。日志先后顺序只决定候选检查顺序，不决定会话归属。

自动候选仅接受回环 HTTP 地址。先验证 `/__bili/plugin/manifest` 的 billion-context 标识，再发送 provider session ID 查询精确映射。过期端口、无效响应和不匹配实例会被排除；多个匹配不会擅自选取。每次打开重新发现，最多检查 16 个地址、同时 4 个请求，每次最多读取 64 个独立实例记录。超出范围时可手动指定实例。

日志关闭、日志位置自定义、daemon 使用另一用户、文件不可读或有效启动记录已超出日志读取范围时，inline 实例无法自动发现。此时可手动填写源地址。自动发现不扫描端口，不注入 Pi，也不启动服务。

旧版已保存的实例地址（包括 `http://127.0.0.1:8787`）保持不变；清空「宿主侧实例地址」并保存后启用自动发现。

浏览器运行在客户端设备，`127.0.0.1` 指客户端本机；daemon 的回环地址则指宿主。远程宿主和移动端必须使用客户端可达的地址或安全隧道。Dashboard 可能包含完整对话内容，应保留回环监听或使用受保护的连接，避免直接公开监听端口。

## 会话定位与失败处理

只读查询 `GET /__bili/plugin/status?conversationId=<provider-session-id>`，使用返回的真实 `sessionId`，不会把 Paseo agent ID 当作 billion-context session ID。不会使用 `fallback=latest`，不按标题、目录或最近活动猜测。

尚无 provider session ID、首轮请求尚未建立压缩会话、实例未收录会话、会话已切换或归档、网络错误、无效响应都会在入口页显示错误。详情查询前后检查会话身份，选择实例后也重新检查；关闭插件会中止进行中的 HTTP 请求。自动发现的 manifest 请求时限为 500 毫秒、会话匹配请求为 1 秒；手动指定或已选定实例的会话查询时限为 5 秒。每个响应上限 256 KiB，不跟随重定向。

胶囊每 3 秒从宿主读取未归档的 agent 列表，原地保留未变化的注册；删除、归档、工作区改变或读取失败时移除旧注册。点击才查询 dashboard，不在后台轮询 dashboard。所有会话都提供入口，未接入 billion-context 的会话会明确提示未找到。

## RPC 注册与启停

业务 RPC 在 `server/rpc.ts` 同步声明，启用状态由本功能内部检查。SDK 0.15.4 的宿主会在插件启动时固定 RPC 名称目录；如果等异步开关读取完成后才注册，会出现 `Plugin zeonest does not contribute RPC zeonest.billion-context.workspaces`，即使客户端入口已经可见。

`server/index.ts` 只在功能启用时激活业务。功能关闭、启动失败或 cleanup 后，已声明的业务 RPC 会先拒绝调用，不读取功能配置、不访问工作区或实例。配置注册仍独立于业务启停。修复构建需要整体重载 Zeonest 才能替换宿主的 RPC 目录，无需重启 daemon。

## 数据与资源

- 使用 Paseo 原生 RPC、设置、侧边栏、屏幕和 composer pill，不依赖其他子功能或壳 helper。
- 通过 Paseo 读取工作区元信息、agent 元信息和 provider session ID；后者仅发送给手动指定或经过 manifest 验证的本机候选实例。
- 自动发现只读上述实例记录和默认日志，忽略符号链接文件。不读取会话文件、数据库或凭据文件，不写入聊天历史，不修改 provider 环境变量、daemon 配置或会话。
- 不安装、启动或启用 billion-context，不创建隧道，不改变 dashboard 内容和主题。
- 清理时移除客户端贡献和定时器，忽略已关闭页面的异步结果，中止服务端请求。
