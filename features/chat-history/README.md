# 历史对话展开

功能 ID：`chat-history`。识别用户消息中的 `<chat-history-summary>...</chat-history-summary>`，把前序对话放进 Chat history 折叠区，当前正文显示在下方。新建分叉对话的历史附件通过补取完整消息识别，无需 Reload agent。历史默认折叠，可在功能配置中改为默认展开。

## 启用

需要 Paseo 0.15.4+。在 Zeonest 功能管理中开启「历史对话展开」，保存后重新加载整个插件。功能默认关闭。

折叠区位于包含摘要的那条消息顶部。分叉摘要位于首条消息时，它就出现在这段对话的开头；插件不移动其他消息，也不创建新的历史记录。

## 展示方式

点击 Chat history 展开，按摘要顺序阅读：

- **Meta**：来源 agent、目录及未标注角色的文本。
- **User**：右侧用户消息，正文可选择复制。
- **Assistant**：助手消息，预览和全文均使用 Paseo 原生 Markdown 展示。
- **Actions**：操作名称与摘要，点击单项展开已保留的详情。

默认每次显示 40 条，点击「显示更多历史」继续阅读；超过 1800 字符的单条内容提供「展开全文」。条数和预览长度均可配置，摘要原文始终完整保留。多段摘要分别折叠；嵌套摘要保留为可选择文本。

当前用户正文使用无额外角色标题的右侧气泡。显示时去掉摘要标签外留下的首尾空行，保留正文内部的换行和缩进；提取出的原始正文不作修改。

「查看摘要原文」显示标签内部的完整文本，方便核对角色划分。Paseo 的摘要用行首 `[User]`、`[Assistant]`、`[操作名称]` 区分条目；原对话若使用了同样的行首格式，划分会有歧义，原文视图可用于核对。代码围栏内的角色标记保留为代码内容。

## 显示配置

在 Zeonest 功能管理中打开「历史对话展开」的配置页。配置保存在当前宿主，保存后通过 Paseo 推送生效，无需重载插件；功能关闭时仍可配置。

| 配置 | 字段 | 默认值 | 范围与行为 |
| --- | --- | --- | --- |
| 默认展开历史 | `defaultExpanded` | `false` | 未手动切换的折叠区跟随设置；手动选择会保留到组件卸载 |
| 单条预览长度 | `previewLength` | `1800` | 0–20000 的整数；`0` 表示直接显示全文 |
| 每次显示条数 | `pageSize` | `40` | 10–200 的整数；包含 Meta、消息和操作 |

配置页保留未保存的草稿。其他客户端修改配置后会提示版本变化；保存发生冲突时，先复制需要的修改，再点击「重新读取」，该操作会丢弃当前草稿。「恢复默认」会重置这三项显示配置。

读取失败或配置无效时，对话区提示错误并暂用默认值，仍可查看历史；配置页提供重新读取和无效配置重置入口。

## 识别范围

历史解析与展示由客户端的 Timeline Transformer + React Native Renderer 完成，识别 `user_message.text` 中成对的摘要标签。正文没有摘要时，还会按消息 ID 匹配补取到的完整消息：

```text
<chat-history-summary>
Chat history from a previous Paseo agent.
Source agent: Example
Source directory: /workspace/example

[User] 检查配置读取逻辑。
[Read] src/config.ts
[Assistant] 已完成检查。
</chat-history-summary>

继续处理错误提示。
```

正文和匹配的完整消息中都没有有效摘要标签时，继续使用原生展示；不解析代码示例中的标签。仅有附件标题 `Chat history` 无法解析历史内容。

命中的用户消息由插件整体重绘，当前正文按可选择的纯文本展示，不复刻该条原生消息的附件胶囊、图片预览和回退菜单。

Paseo 0.15.4 的分叉摘要保留 User、Assistant 和部分操作摘要，操作的完整参数、结果及状态可能已被省略。功能展示已有信息，不补造操作状态；遇到 `[Earlier chat history omitted]` 或 `[Message truncated]` 时会提示来源摘要已省略或截断内容。

## 新对话的历史附件补取

Paseo 0.15.4 新建分叉对话时，首条消息的 Chat history 保存在独立的 `chat_history` 文本附件中，当前正文放在 `text`。[宿主的用户消息投影](https://github.com/getpaseo/paseo/blob/v0.15.4/packages/app/src/plugins/timeline/projection.ts#L44-L53)不传递附件，[确认消息 ID 时](https://github.com/getpaseo/paseo/blob/v0.15.4/packages/app/src/types/stream.ts#L261-L268)也保留本地展示。因此，只解析当前正文不能识别这类附件。

功能启用后，会先订阅 agent 的实时消息，再通过公开的 `timeline.refetch({ projection: "canonical" })` 补取完整消息。收到带摘要的完整用户消息后，以 `clientMessageId` / `messageId` 建立固定快照，移除旧 Transformer 并重新注册，让 Paseo 重新计算已显示的那条消息。摘要来自完整消息，当前正文仍使用本地原文；已经包含摘要的正文优先直接解析，避免重复添加历史。

这条路径只读取消息，不重开 agent 会话、不发送新消息。完整消息到达前，界面可以短暂保留原生附件；到达后按显示设置切换为历史折叠区，不保证发送后的第一帧就已折叠。

消息 ID 缺失、相互矛盾或在已观察消息中重复时，不借用其他消息的历史。读取或订阅失败会保留原生展示，并以 1–30 秒退避重试；断线恢复和时间线替换会清除旧匹配，再补取。关闭功能后取消订阅与待执行任务，迟到的响应不再注册 Transformer。

## 数据访问与生命周期

历史内容在客户端解析和展示。功能会读取当前宿主的 agent 目录、订阅实时消息，并补取 canonical 时间线；不读取历史文件，不把摘要写回服务端或发送给 agent。Markdown 的链接行为由 Paseo 提供。折叠、分页和全文展开状态保存在当前组件内。

补取有明确上限：初始观察最近更新的 32 个未归档 agent，随后跟踪目录中的新建/更新；超过 32 个时释放较早观察的 agent。每次追补最多读取 4 页，每页 100 条，最多并发 4 个 agent 的读取任务。内存缓存最多保留 256 条用户消息的 ID 与摘要，总计约 400 万字符；超过 100 万字符的完整消息不进入补取匹配，也不会截断后展示。超出观察、分页或缓存范围的消息依赖正文中的摘要标签，未匹配时继续使用原生展示。

显示配置使用 Paseo 原生 Settings API，通过内置 RPC 读写宿主级配置并同步到客户端；服务端只注册本功能的配置定义。配置不保存历史内容。

关闭功能并重载插件后释放目录与时间线订阅、清除内存缓存，并移除 Transformer 和 Renderer，消息恢复宿主的原生展示；配置入口和已保存的显示偏好仍然保留。

`tests/live-attachment.test.ts` 按 Paseo 0.15.4 的用户消息投影建立输入模型，确认未补取时附件仍不在转换输入中。`tests/backfill.test.ts` 使用 SDK 替身覆盖先订阅再读取、实时消息与补取竞态、断线追补、epoch 替换、ID 冲突、分页/并发/内存上限及迟到响应清理；注册与 UI 测试检查同一消息对象在重新注册后生成默认折叠区，并验证注册失败时的回退。测试不运行 Paseo 宿主，不代表已完成真实 UI 验收。

真实 Paseo 的验收步骤：

1. 在获准安装、开启并重载插件后，打开正文包含摘要标签的消息，确认历史默认折叠，当前用户气泡没有额外标题或大块空白。
2. 展开历史与操作详情，核对角色、来源、Markdown 和原文内容；确认长助手消息在「展开全文」前后均按 Markdown 展示，测试多段摘要。
3. 在宽屏、compact、明暗主题下检查布局和可访问性，检查空摘要及标签不完整时的回退。
4. 在 Paseo 0.15.4 新建分叉对话并发送首条消息，分别检查有正文和仅 Chat history 附件的情况，确认完整消息到达后自动出现折叠区，正文不变，无需 `Reload agent`。断线后重新连接，检查遗漏的历史被补取；检查读取失败时原生消息仍可见。
5. 在配置页修改默认展开、预览长度和分页条数，确认保存后更新；检查 `0` 预览长度、跨客户端版本冲突、重新读取及恢复默认。
6. 关闭功能并重载，确认原生消息恢复且配置入口仍可用。
