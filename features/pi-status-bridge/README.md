# Pi 状态桥接

功能 ID：`pi-status-bridge`，默认关闭。使用仓库锁定的 Paseo SDK 0.15.4，不修改壳、Paseo 本体或目标 Pi 插件。

## 行为

- 捕获 Pi RPC 模式下原生 `ctx.ui.setStatus(key, text)`，每个 key 在对应 agent 的聊天框上方显示一个 Paseo 原生胶囊。不同 agent 的同名 key 相互独立。
- 状态更新时原位更新胶囊；清除状态、关闭/归档 agent、卸载功能时移除。空白状态不占位置。
- 胶囊文字不再按字符数截断，也不提供长度设置；实际可见宽度由 Paseo 原生布局决定。点击打开全文弹层，正文可选择、滚动和复制。去掉终端 ANSI 样式及控制字符，保留正文和换行。
- 可以把状态 key 映射到一个已有的 Pi 插件 `/命令`。弹层显示准确命令和提示，只有再次点击「执行 Pi 展开命令」才发送。
- Pi 的普通 `select`、`confirm`、`input`、`editor` 对话框和通知继续由 Paseo 内置 Pi provider 处理，本功能不伪造终端界面。
- 观察器约每 200ms 合并发送状态，空闲时每 5 秒发送快照；客户端约每秒轮询一次。通道超过 16 秒无快照时隐藏旧状态并显示告警，不把旧数据显示为当前状态。

Pi 原生 `setStatus` 只有 key 和文本，没有通用的点击回调。因此「查看全文」自动可用，「Pi 侧展开」需要显式配置目标插件提供的命令。

## 接入

无需包装器、额外 Pi 扩展或修改 `agents.providers.pi.command`。本功能不会自动安装/启用 Zeonest，不修改 `pluginsEnabled` 或 daemon 配置，也不重启 daemon。

1. 获准安装 Zeonest 后，在 Zeonest 开启本功能，整体重新加载插件。
2. 新建 Pi agent，或者在已有 agent **空闲后**手动重新打开会话。运行中的进程不会补注入，不要中断正在执行的轮次。
3. Pi 插件发布状态后应出现独立胶囊。全文顶部就是配置映射时使用的精确 key。

采用原生 `agent.open.before`（SDK 的 `agent.session_open` 别名所对应的事件），在交互式 Pi 会话启动环境中追加 `NODE_OPTIONS --import`，使观察器早于 Pi 的 stdout 接管运行。hook 返回包含新环境的完整请求；Paseo 0.15.4 会复制传入的请求，只修改副本而不返回时，注入不会生效。保留原有 Node options，优先级为会话环境 > Pi provider 环境 > daemon 进程环境；不会持久化到 agent 配置。没有凭据、非 RPC 模式或 worker 中不启动观察。启动状态先在内存中收集，直到真实 agent 的首个 `get_state` 成功响应才开始发送；Paseo 0.15.4 另起的 MCP 命令探测进程只请求 commands，不会发布到正式会话通道。

宿主及实际运行 Pi 的 Node 需 22+。自定义启动脚本必须把注入环境传给实际的 Node Pi RPC 进程；清除 `NODE_OPTIONS`、改用非 Node 的 Pi 可执行文件或吞掉 stdout 的特殊启动器不在兼容范围内。不要把同一份已注入环境主动复制给多个独立 Pi 进程。

观察器从随包 server bundle 内嵌的静态程序自动准备到宿主的 `~/.zeonest/pi-status-bridge/observer-<内容哈希>.mjs`，只使用 Node 内建模块，不下载代码、不安装依赖、不调用仓库工具。文件为私有权限，以完整文件原子发布，拒绝目录/文件软链接及被改动的同名文件，不自动覆盖。准备或 hook 失败只在 daemon 日志诊断，保留原启动环境；注入成功后若导入文件被人为删除、Node 不支持预加载或原有 options 无效，仍可能导致 Node 启动失败，需修复运行环境。

更新后会自动使用新哈希的脚本。旧文件保留，避免影响已启动/正在打开的会话；不代删用户文件。关闭功能并整体重载后，新会话不再注入；旧观察器因令牌失效停止 HTTP，用户的 Pi 进程不被杀死。确认没有会话仍依赖旧文件后，可手动删除该目录。

### 从旧包装器实现迁移

如果曾手动配置旧版包装器，请自行把 `agents.providers.pi.command` 恢复成记录的原始命令，按 Paseo 原有流程应用配置，再在空闲时重新打开会话。本功能不会自动改回 daemon 配置。包装器准备 RPC、生成文件按钮和 provider 配置片段已删除；不支持新旧接入叠加。

## 显示与展开配置

配置属于本功能的原生 host settings 文档，ID 为 `pi-status-bridge-preferences`、版本 2：

```json
{
  "hiddenKeys": [],
  "actions": [
    { "key": "my-status", "command": "/my-status details" }
  ]
}
```

- `hiddenKeys`：精确匹配需要隐藏的 key，对本宿主所有 Pi agent 生效，不改变 Pi 自己的状态。
- `actions`：key 与单行 `/命令 [固定参数]` 的一对一映射。支持 Pi 的命令重名后缀，如 `/review:1 details`。不执行 shell，不从状态内容插值，不提供任意客户端命令执行 RPC。
- 版本 1 文档自动迁移，丢弃原 `labelLength`，保留隐藏 key 和命令映射。
- 保存后在下一次轮询生效，不必重载功能。保存使用所见 revision；冲突、无效文档和连接错误会显示并保留草稿，不静默覆盖另一客户端的设置。
- 功能开关仍通过整体插件重载生效。设置入口始终可用；功能关闭时不注册业务 hooks、准备脚本、监听端口或轮询状态。
- 业务 RPC 在 `server/rpc.ts` 启动时同步声明，适配 0.15.4 的固定 RPC 目录。未启用、启动失败、停止后均先拒绝业务调用，不读取状态或发送命令；启用后才连接本功能的活动桥接。

展开前验证状态仍有效、映射与用户看到的命令一致、目标仍为同工作区的 Pi agent，并检查空闲状态、正在进行的 turn 和待处理权限。查询当前已加载命令后再检查一次 agent，未找到的命令和技能不会发送。重复点击由客户端/服务端锁抑制。

**只映射可信插件的命令。** 0.15.4 的公开命令列表把插件命令和提示词模板都归为 `command`，不能据此保证绝不会调用模型。不要映射模板、技能或具有破坏性的管理命令。插件自己的命令也可能调用模型或修改文件/会话，沿用 Pi/Paseo 原有权限。其他客户端同时操作或插件在检查后卸载仍存在竞态，SDK 不提供原子的「验证并调用扩展回调」。本功能不主动取消、重载或排队 agent。

## 兼容边界

- 当前针对内置 provider ID `pi`；不自动推断自定义 `extends: pi` profile、ACP、其他 provider 或 Pi TUI 进程。
- 只有在 RPC 模式真正发布的 `setStatus` 会被桥接。仅在 TUI 模式运行的状态代码、`setFooter` 自定义绘制、`setWidget`、工具结果展开不是状态来源。
- `ctx.ui.custom()`、终端点击、快捷键和任意 TUI 组件没有通用跨端协议，不能通过命令映射自动变成 Paseo 弹层；目标插件需已有 RPC 可用的对话框/通知实现。
- Pi 插件动态卸载若未发送清除状态，无法仅凭输出知道 key 已失效。执行 Pi `/reload` 或更换插件后，建议在空闲时手动重新打开会话，避免未清除的旧 key。
- 每次整体重载 Zeonest 都会换端口并失效旧令牌。已运行的 Pi 进程不会自动注入新环境；需要在空闲时手动重新打开已有会话，或新建 agent。
- 不从会话历史恢复状态。会话重启后从新的状态发布开始；如果插件自己只发布摘要，桥接不能恢复未发布的详情，需要使用该插件的展开命令。
- 观察 `process.stdout.write`，不拦截 `fs.writeSync(1, ...)`、原生代码直接写文件描述符或任意非标准 RPC 输出。当前真实 Pi 1.5.2 的 `takeOverStdout()` 保存了预加载后的 writer，已做真实进程验证；其他 Pi 版本需重新验证。

## 数据、安全与资源

`Pi 原始 stdout writer → 预加载观察器 → 127.0.0.1 随机端口 → 功能内存 → Paseo RPC → 原生胶囊`。

- 监听仅在功能启用后的首个交互式 Pi 会话打开时创建；history 会话、无工作区会话和其他 provider 不注入。
- 每会话独立地址和随机 256-bit bearer token；重新打开/关闭/归档使旧 token 失效。观察器在应用代码启动前清除自身通道环境变量并恢复原 `NODE_OPTIONS`，子进程/嵌套 Pi 不默认继承注入；worker 不启动观察。保留用户原有预加载项。这是可信本地插件的隔离措施，不是抵抗同用户恶意进程或其他预加载代码的安全沙箱。
- HTTP 拒绝浏览器 Origin、未知令牌、错误方法/路径、畸形数据和超限 body。带递增序号的完整快照防止迟到更新复活已清除状态；key 不作为路径或 shell 输入。
- 正文和令牌不写入磁盘、聊天历史或日志，不请求外部网络。已授权连接此宿主的 Paseo 客户端可通过插件 RPC 读取状态；这不是秘密信息保险箱。展开命令及其结果可能按原生行为进入会话记录。
- 每会话最多 128 项；key 最多 256 个 JS 字符，单项文本最多 65,536 个 JS 字符，总状态约 500KB，HTTP body 上限 512KiB。超限会跳过对应更新并告警，**不静默截断成「全文」**。过长的其他 RPC 行仍正常写出，只跳过桥接解析。
- 不启动额外子进程，不代理 stdin/stderr、信号或退出码。writer 原样调用原函数，保留 receiver、参数/回调对象、编码、错误和返回值/背压；随后只解析成功写出的数据，支持分片 UTF-8。HTTP 不在 write 路径中等待，不创建可维持 Pi 存活的计时器/套接字。
- HTTP 不可用时只向 stderr 诊断并退避重试，持续故障约 16 秒后停止转发。403/410 立即停止，不无限轮询旧端口，Pi 继续工作；恢复需手动重新打开空闲会话。进程退出后的旧状态由原生关闭事件或租约清除。
- cleanup 注销 hooks、关闭监听与连接、清空令牌/状态、停止客户端计时器并移除胶囊；迟到结果不重新创建胶囊，不杀死 agent。
