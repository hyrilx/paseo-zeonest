# 构建工作台体验重构：实现与验收

以 `main` 的 `c1908e4` 为基线，按顺序移植调查与原型提交 `2ed08a0`、`ee9e5fc`。原型和设计依据见 [体验调查](ux-review.md)；正式面板使用 Paseo 工作区贡献、React Native 和宿主主题。

## 交互与实现

- 宽屏同时显示目标、配置与命令、工具链；compact 通过页签切换这三个区域。顶部主操作和阻塞原因不随内容滚动。字段错误就地显示，扫描提醒和运行失败分别出现在目标区和运行详情。
- 运行区可拖动分隔条调整高度；键盘用 ↑/↓ 微调，Shift 配合方向键可大步调整，Home/End 跳到上下限。运行历史与详情各自滚动。新运行打开输出；手动换记录保留输出或产物页签。
- 当前工作区的成功探测触发一次目标刷新；失败与历史成功不触发刷新。刷新保留草稿和原目标；出错保留上次列表并可重试。「查看新目标」只切换列表视图，不选目标，也不执行命令。
- Gradle 按项目声明的 Wrapper 分发版本和本机 Java 版本提示运行 JVM 的兼容性，将 `java -version` 作为启动检查单独显示。检测到 daemon JVM criteria、JVM 覆盖或版本证据不足时显示「兼容性未确认」。优先推荐满足已知版本范围的本机候选；保留用户已选工具，即使它已失效或不适用。面板不修改项目 JVM 设置。
- 只有当前工作区、项目声明、工具签名和探测上下文匹配时，才提供该任务的探测选项。未编辑的临时配置可带入这些选项；手工编辑或已保存的选项不被覆盖。执行 Gradle 任务前仍要核对预览并显式确认。

## 回归结果

使用 `agent-browser` 驱动正式面板源码的 React Native Web 预览。宿主主题、原生设置组件和 RPC 传输使用本地替身；下表前三条路径通过实际 `Workbench` 服务在隔离目录运行，故障路径由替身注入。

| Cargo | 检查工具后直接构建两次，未执行探测；默认构建和 `--release` 均退出 `0`，分别观察到 `target/debug/workbench-demo` 与 `target/release/workbench-demo`。新记录打开输出；手动切换记录时保留产物页签，再切回输出可查看该次运行。 |
